# 0.2.0

Public launch release focused on project-aware migration completion and stronger diagnostics.

## Added

- Migration-aware completion for `migrate`:
  - `python manage.py migrate <TAB>` completes apps that have migrations.
  - `python manage.py migrate accounts <TAB>` completes migration names plus `zero`.
- Cache schema v2 with `schema_version`, `migrations`, and `warnings`.
- Disk-based migration discovery that respects `settings.MIGRATION_MODULES`.
- Internal Python completion helper (`django_completion._complete`) used by bash and zsh scripts.
- `uv run python manage.py` completion support.
- `autocomplete status --verbose` for full cache, hook, script, and package diagnostics.
- Script version tracking: generated completion scripts include a `# django-completion version: ...` marker.
- Status reporting for current, outdated, missing, and unversioned installed scripts.

## Changed

- Shell templates are now thin wrappers that call the internal Python helper instead of carrying completion decision logic in shell snippets.
- `autocomplete status` now reports schema freshness, migration-app counts, warning counts, hook state, and installed script currency.
- README and docs now lead with migration completion and document v0.2.0 behavior.

## Notes

- Tab completion still reads only the local cache file. It does not import Django, touch the database, or make network calls.
- `django-admin`, fish shell, native Windows/PowerShell support, custom aliases, and global options before the command remain out of scope for v0.2.0.
