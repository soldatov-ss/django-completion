# 0.2.5

UX fixes and completion enhancements surfaced during real-world testing.

## Fixes

- **Shell detection**: `autocomplete install` now checks `$ZSH_VERSION` and `$BASH_VERSION` (set by the shell itself) before falling back to `$SHELL`. This fixes the case where the login shell is bash but the user is running in zsh — the correct RC file is now detected.
- **Re-install source reminder**: running `autocomplete install` when the hook is already present now prints a `source` reminder so the user knows to reload their shell to pick up the updated script.
- **Bash file-completion fallback**: `python manage.py makemigrations <TAB>` (and any other command that returns no candidates) no longer falls back to filename completion and dumps every file in the project directory. The bash template now calls `compopt +o default` when a `manage.py` token is detected in the command line.
- **"Did you mean?" for autocomplete subcommands**: typing `python manage.py autocomplete states` now shows `Did you mean 'status'?` — matching the suggestion Django already provides for top-level command typos.

## Improvements

- **Subcommand option completion**: `autocomplete status --<TAB>` now completes `--verbose`; `autocomplete install --<TAB>` completes `--shell`; `autocomplete install --shell <TAB>` completes `bash` and `zsh`.
- **Status output colors**: `installed` / `current` labels are shown in green; `not installed` / `outdated` labels in yellow.
- **Subcommand help text**: each subcommand's own `--help` output now shows a one-line description above its options (e.g. `python manage.py autocomplete status --help`).

## Docs

- `docs/troubleshooting.md`: added a section explaining the difference between the shell **hook** (the `source` block in your RC file) and the **script** (the completion file under `~/.local/share/django-completion/`).
- `docs/troubleshooting.md`: updated the "Wrong shell was detected" entry to mention the new `$ZSH_VERSION` / `$BASH_VERSION` detection order.
