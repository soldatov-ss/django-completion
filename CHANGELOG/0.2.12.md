# 0.2.12

Repositioning release: README, docs, and demo now lead with custom management command completion. No code or behaviour changes.

## Changes

- **README leads with custom management commands**: The intro and "What Completes" section now open with the completion case that has no built-in workaround — your project's own commands and their introspected flags. Migrations and app labels remain fully documented but are no longer the hook. The PyPI page inherits this since the README is baked into each release.

- **New demo.gif**: The opening beat now shows a custom command completing (`imp<TAB>` → `import_articles`, then `--<TAB>` → its introspected flags with descriptions), followed by migrate app labels and migration names. Recorded with vhs from the updated `demo/demo.tape`.

- **Demo project gains a custom command fixture**: `demo/blog/management/commands/import_articles.py` with `--source`, `--limit`, `--since`, and `--dry-run` options — demo fixture only, not library code. `demo/RECORDING.md` updated to match the new beats.

- **Same reorder in docs**: `docs/index.md` opens with a custom-command example and explains that the cache covers custom commands like built-ins; `docs/comparison.md` gains a "Tab completion without importing Django" row and leads the "Use django-completion" guidance with the custom-commands case.

- **Homebrew name-collision note**: README and docs homepage now state that the `django-completion` Homebrew formula is an unrelated static bash script, to disambiguate search results.
