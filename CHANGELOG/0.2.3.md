# 0.2.3

Internal quality improvements: dead code removal, better error visibility, testable core mechanism, and a small locality fix. No behaviour changes for end users.

## Removed

- `fuzzy.py` deleted. The module was scaffolded early for a "did you mean?" feature that was never wired into a call site. Django already shows "Unknown command: '…'. Did you mean …?" natively at its command-discovery layer, so the feature was doubly covered. Keeping the file implied the package did something it did not.

## Changed

- Auto-refresh hook (`apps.py`) extracted into two named module-level functions — `_make_execute_hook` and `_refresh_safely` — so the mechanism that fires after every `manage.py` command can be unit-tested. Error reporting switched from `warnings.warn` (which pointed at Python's threading internals from a background thread and was invisible to users) to `logging.getLogger("django_completion")`.

- `_migration_app_labels` in `_complete.py` now reuses the `_app_labels` helper to build its origin lookup instead of re-parsing `cache["app_labels"]` inline. Behaviour is identical; parsing logic is concentrated in one function.

## Fixed

- Command introspection failures in `build_cache()` are now recorded in the `warnings` list instead of being silently discarded. If a management command class cannot be loaded or its parser raises, a warning string (including the command name and exception text) is appended. Users can see it via `python manage.py autocomplete status --verbose`. The command still appears in `data["commands"]` (it was discovered by `get_commands()`), but its `command_options` entry is `[]`.
